# Unknown Monitor

پنل VPN بر پایهٔ هستهٔ Xray با ساب‌لینک، به‌همراه مانیتورینگ شبکه، مصرف لحظه‌ای ترافیک و تست کارایی برای سرورهای اوبونتو

[English](README.md) | **فارسی**

Unknown Monitor یک پلتفرم خودمیزبان (self-hosted) برای مانیتورینگ مجموعه‌ای از سرورهای اوبونتو و اجرای تست‌های کارایی شبکه بین آن‌هاست. هستهٔ آن **iperf3** است: ایجنت، iperf3 را با خروجی JSON اجرا می‌کند و سرور نتایج را تحلیل و ذخیره می‌کند. داشبورد وب تم تیره (زغالی) با رنگ‌های سبز زمردی دارد.

همهٔ اعداد روی صفحه از اندازه‌گیری واقعی می‌آیند: شمارنده‌های کرنل، `/proc`، iproute2، iperf3، ping، traceroute، mtr یا یک کوئری واقعی DNS. هیچ دادهٔ ساختگی یا درون‌یابی‌شده‌ای نمایش داده نمی‌شود؛ اگر گزارشی نرسد، روی نمودار هم جای خالی می‌ماند.

## امکانات

| بخش | توضیح |
|---|---|
| **پنل VPN (هستهٔ Xray)** | چندسروره؛ پروتکل‌های VLESS، VMess، Trojan و Shadowsocks (و 2022) با ترنسپورت‌های TCP، XHTTP، WebSocket، gRPC و HTTPUpgrade و امنیت TLS، REALITY و XTLS Vision. برای هر کاربر می‌شود حجم، تاریخ انقضا و اینباندهای مجاز تعیین کرد. ساب‌لینک برای v2rayNG، Hiddify، Streisand و Clash Meta، و صفحهٔ وضعیت کاربر با QR. مصرف هر کاربر ثبت می‌شود و قطع خودکار با تمام شدن حجم یا زمان انجام می‌شود. |
| **مصرف لحظه‌ای واقعی** | هر ایجنت هر ۲ ثانیه سرعت فعلی ترافیکی را که واقعاً از سرور عبور می‌کند، از روی شمارنده‌های کرنل گزارش می‌دهد. برای این کار هیچ تستی اجرا نمی‌شود و ترافیک اضافه‌ای ساخته نمی‌شود. |
| **حجم مصرفی روزانه و ماهانه** | دانلود و آپلود هر سرور و کل سرورها برای امروز، این ماه و ۳۰ یا ۹۰ روز اخیر، با نمودار روزانه. فقط کارت‌های شبکهٔ فیزیکی شمرده می‌شوند تا ترافیک docker، wg، tun و bridge دوبار حساب نشود. |
| **مانیتورینگ چند سرور** | CPU، حافظه، swap، دیسک، load، uptime، وضعیت‌های TCP، retransmitها و برای هر اینترفیس: بیت بر ثانیه، پکت بر ثانیه، خطا و drop. هر ۱۰ ثانیه از شمارنده‌های کرنل جمع‌آوری می‌شود. |
| **نمودار لحظه‌ای** | فید زنده با WebSocket برای پهنای باند کل و هر اینترفیس، به‌همراه نمودارهای تاریخی (۱۵ دقیقه تا ۳۰ روز) با بازه‌بندی سمت سرور. |
| **تست سرعت** | iperf3 با TCP/UDP در حالت آپلود، دانلود (`-R`) و دوطرفه؛ با stream موازی، bitrate، omit و IPv6. نمایش throughput هر بازه، retransmit، jitter، packet loss و مصرف CPU. |
| **ابزارهای عیب‌یابی** | Ping (RTT، loss، jitter)، traceroute (UDP/ICMP/TCP)، MTR و DNS (هر نوع رکورد، resolver دلخواه، UDP/TCP، زمان پاسخ). |
| **موجودی سیستم** | اینترفیس‌ها و آدرس‌ها، routeهای IPv4/IPv6، اتصال‌های فعال و تنظیمات DNS. |
| **زمان‌بندی** | تست‌های تکرارشونده برای داده‌های تاریخی و هشدارها. |
| **هشدار** | قانون روی متریک‌های سیستم، اینترفیس، تست‌ها و در دسترس بودن؛ اعلان با webhook (سازگار با Slack) و ایمیل؛ تأیید (ack) و تاریخچه. |
| **تحلیل تاریخی** | روند throughput، RTT (میانگین و p95)، loss و jitter برای هر سرور و مقصد. |
| **امنیت** | نقش‌ها (admin / operator / viewer)، هش رمز argon2id، قفل حساب پس از تلاش ناموفق، محافظت CSRF، لاگ ممیزی، توکن ثبت‌نام یک‌بارمصرف، اعتبارنامهٔ جداگانه و قابل‌ابطال برای هر ایجنت، TLS و سرویس‌های systemd با حداقل دسترسی. |
| **عملیات** | نصب با یک دستور روی اوبونتو، migration دیتابیس، اسکریپت ارتقا، بکاپ روزانهٔ تأییدشده، بازیابی و حذف خودکار دادهٔ قدیمی. |

## پیش‌نیازها

- سرور **Ubuntu 22.04 یا 24.04**
- دسترسی root
- برای SSL رایگان و خودکار: یک دامنه یا ساب‌دامنه با رکورد A که به IP سرور اشاره کند. بدون دامنه هم با IP نصب می‌شود.

## نصب (فقط یک دستور)

</div>

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/amirali272/ipf3/claude/gracious-ramanujan-enb5r9/install.sh?$(date +%s))
```

<div dir="rtl">

یا اگر مخزن را دارید:

</div>

```bash
git clone -b claude/gracious-ramanujan-enb5r9 https://github.com/amirali272/ipf3.git
cd ipf3 && sudo ./install.sh
```

<div dir="rtl">

نصب‌کننده یک منو نشان می‌دهد:

| گزینه | کاربرد |
|---|---|
| **1 — Install panel + agent on this server** | برای سرور اول: پنل نصب می‌شود و همین سرور هم مانیتور می‌شود |
| **2 — Install panel only** | فقط پنل |
| **3 — Add this server to an existing panel** | اضافه کردن سرورهای دیگر به پنل |
| **4 — Upgrade an existing installation** | ارتقا به نسخهٔ جدید (قبلش خودکار بکاپ گرفته می‌شود) |

برای نصب پنل فقط این‌ها پرسیده می‌شود:

۱. **دامنه یا IP**: مثلاً `monitor.yourdomain.com`. اگر دامنه به سرور اشاره کند، گواهی SSL رایگان Let's Encrypt خودکار گرفته می‌شود. اگر نشود، خودکار گواهی self-signed ساخته می‌شود و نصب متوقف نمی‌شود.
۲. **ایمیل** برای اطلاع‌رسانی انقضای SSL (اختیاری)
۳. **نام کاربری و رمز مدیر**: رمز حداقل ۱۲ کاراکتر و شامل سه مورد از این‌ها: حرف کوچک، حرف بزرگ، عدد، علامت
۴. **منطقهٔ زمانی** برای آمار روزانه و ماهانه، مثلاً `Asia/Tehran`
۵. **فایروال** (اختیاری)

قبل از شروع، یک خلاصه نمایش داده می‌شود. در پایان آدرس پنل و نام کاربری نمایش داده می‌شود.

### اضافه کردن نود VPN روی سرور دیگر

اینباندها لازم نیست فقط روی سرور پنل باشند.

۱. در پنل به **VPN ← Inbounds & nodes ← Add node** بروید، یک اسم بدهید و **Generate command** را بزنید.
۲. دستوری را که نشان می‌دهد کپی کنید و روی سرور جدید با کاربر root اجرا کنید. چیزی نمی‌پرسد؛ ایجنت و Xray نصب می‌شوند و نود به پنل وصل می‌شود.
۳. وقتی پنجره **Connected** را نشان داد، با **New inbound** اینباند بسازید و در فیلد سرور، همین نود را انتخاب کنید. روی نود، پورت 443 آزاد است (اگر فایروال روشن است: `ufw allow 443`).

</div>

```bash
bash <(curl -fsSL "https://raw.githubusercontent.com/amirali272/ipf3/claude/gracious-ramanujan-enb5r9/install.sh?$(date +%s)") --node --panel https://panel.yourdomain.com --token ipf3e_XXXX --name de-1
```

<div dir="rtl">

### اضافه کردن سرورهای دیگر (فقط مانیتورینگ)

۱. در پنل به **Servers ← Enroll server** بروید و یک توکن بسازید.
۲. روی سرور جدید همان دستور نصب را اجرا کنید و گزینهٔ **3** را بزنید.
۳. آدرس پنل و توکن را وارد کنید.

اگر پنل گواهی self-signed داشته باشد، نصب‌کننده اثر انگشت گواهی را نشان می‌دهد تا با پیام پایان نصب پنل مقایسه و تأیید کنید.

## راه‌اندازی VPN

۱. **سرور VPN (نود):** موقع نصب، به سؤال «Use this server as a VPN node» جواب **بله** بدهید. روی سرورهایی که از قبل ایجنت دارند: `sudo ./install.sh` ← گزینهٔ **4 (Upgrade)** ← بله.
۲. **ساخت اینباند:** در پنل به **VPN ← Inbounds & nodes ← New inbound** بروید. پیشنهاد: **VLESS · REALITY · Vision**؛ نه دامنه می‌خواهد نه گواهی. دکمهٔ **Generate** کلیدها را می‌سازد.
   - روی خود سرور پنل، پورت 443 دست پنل است؛ پورت دیگری مثل 8443 یا 2053 انتخاب کنید.
   - اگر فایروال روشن است، پورت را باز کنید: `ufw allow 8443`
۳. **ساخت کاربر:** در **VPN ← Users ← New user**، حجم (GB) و مدت (روز) را تعیین کنید.
۴. **ساب‌لینک:** دکمهٔ **Sub link** را کپی کنید یا QR را در v2rayNG، Hiddify یا Streisand اسکن کنید. اگر کاربر لینک را در مرورگر باز کند، صفحهٔ وضعیت (حجم باقی‌مانده، تاریخ انقضا، QR و دکمه‌های افزودن به برنامه) را می‌بیند.

با تمام شدن حجم یا زمان، کاربر حداکثر ظرف ۱۰ ثانیه قطع می‌شود. با **Reset traffic** یا تمدید، دوباره وصل می‌شود. **Revoke links** همهٔ کانفیگ‌ها و ساب‌لینک قبلی را باطل می‌کند.

### آی‌پی‌های متصل و برنامه‌ها

- در صفحهٔ **Users**، کنار هر کاربر آنلاین نشان `N IP` دیده می‌شود. با کلیک روی آن یا از منوی ⋮ ← **Activity** این‌ها را می‌بینید:
  - آی‌پی‌های متصل و نودی که هر کدام به آن وصل است
  - برنامه‌هایی که ساب را آپدیت کرده‌اند (مثل v2rayNG، Hiddify، Streisand، Happ) با نسخه‌شان
- صفحهٔ ساب‌لینک (وقتی کاربر لینک را در مرورگر باز می‌کند) فارسی/انگلیسی است و حجم، انقضا، دستگاه‌های متصل، برنامه‌ها، QR و دکمه‌های افزودن سریع را نشان می‌دهد.
- برای نمایش آی‌پی‌ها، نودها هم باید آپدیت شوند.

### اوت‌باند و روتینگ

در **VPN ← Outbounds & routing**:

- **Add outbound:** لینک یک کانفیگ را پیست کنید (vless، vmess، trojan، ss، socks، http یا wireguard). یک پیش‌نمایش از آن نشان داده می‌شود. می‌توانید تعیین کنید روی همهٔ نودها باشد یا فقط روی نودهای انتخابی.
- **Add rule:** قانون تعیین می‌کند ترافیک به Direct برود، Block شود یا از یک اوت‌باند خارج شود. شرط‌ها می‌توانند دامنه (`geosite:google`)، IP (`geoip:ir`)، کاربر، اینباند، پورت یا پروتکل باشند. چند قالب آماده هم هست: «سایت‌های ایرانی مستقیم»، «بلاک تبلیغات»، «همهٔ ترافیک از اوت‌باند» و «کاربران خاص از اوت‌باند».
- قانون‌ها از بالا به پایین بررسی می‌شوند و اولین قانونی که بخورد، مسیر را تعیین می‌کند. ترتیب را با فلش‌ها عوض کنید.

بخش‌های مانیتورینگ و ترافیک پروژهٔ قبلی همه در منوی **Monitoring & traffic** جمع شده‌اند.

راهنمای کامل (انگلیسی): [docs/VPN.md](docs/VPN.md)

## ارتقا (Upgrade)

ساده‌ترین راه: همان دستور نصب را اجرا کنید و گزینهٔ **4** را بزنید. یا به‌صورت دستی:

</div>

```bash
# سرور اصلی (قبل از ارتقا به‌صورت خودکار بکاپ گرفته می‌شود)
cd ipf3 && git pull
sudo ./deploy/upgrade-server.sh

# هر ایجنت
cd ipf3 && git pull
sudo ./deploy/upgrade-agent.sh
```

## بکاپ و بازیابی

بکاپ هر شب به‌صورت خودکار در `/var/backups/ipf3` گرفته می‌شود (۱۴ روز نگهداری). حتماً از این پوشه یک کپی خارج از سرور نگه دارید.

</div>

```bash
# بکاپ دستی
sudo /opt/ipf3/deploy/backup.sh

# بازیابی
sudo ./deploy/restore.sh /var/backups/ipf3/ipf3-db-<تاریخ>.dump \
     --config /var/backups/ipf3/ipf3-config-<تاریخ>.tar.gz
```

## حذف کامل

دستور نصب را اجرا کنید و گزینهٔ **5 — Uninstall completely** را بزنید، یا مستقیم:

</div>

```bash
cd ~/ipf3 && git pull
sudo ./deploy/uninstall.sh
```

<div dir="rtl">

برای تأیید باید کلمهٔ `DELETE` را تایپ کنید. این‌ها حذف می‌شوند: سرویس‌ها، دیتابیس و همهٔ اطلاعات (کاربران، تاریخچه، آمار مصرف)، تنظیمات و کلیدها (`/etc/ipf3`)، فایل‌های برنامه، سایت nginx، گواهی SSL دامنه، کاربرهای سیستمی و لاگ‌ها.

دو چیز را می‌پرسد:
- بکاپ‌های `/var/backups/ipf3` هم حذف شوند؟
- بسته‌های نصب‌شده (postgresql، nginx، certbot، iperf3، …) هم حذف شوند؟ فقط وقتی «بله» بزنید که برنامهٔ دیگری روی سرور از آن‌ها استفاده نمی‌کند.

حذف بدون هیچ سؤالی (همه‌چیز همراه بکاپ‌ها و بسته‌ها):

</div>

```bash
sudo ./deploy/uninstall.sh --yes --remove-backups --remove-packages
rm -rf ~/ipf3
```

<div dir="rtl">

اگر فقط ایجنت را از یک سرور حذف می‌کنید، بعدش آن سرور را از پنل هم پاک کنید: **Servers ← نام سرور ← Settings ← Delete**.

## رفع مشکلات رایج

| مشکل | راه‌حل |
|---|---|
| سرور **Offline** است | `journalctl -u ipf3-agent` را ببینید. خطای TLS یعنی `--ca-file` لازم است؛ خطای 401 یعنی اعتبارنامه باطل شده و باید با `--reenroll` دوباره ثبت‌نام کنید. |
| تست iperf3 با خطای «unable to connect» | روی مقصد `systemctl status ipf3-iperf3` را چک کنید و فایروال (TCP و برای UDP، UDP) را باز کنید. |
| «the server is busy running a test» | هر سرور iperf3 در هر لحظه فقط یک تست را می‌پذیرد؛ زمان‌بندی‌ها را با فاصله تنظیم کنید. |
| رمز مدیر را فراموش کرده‌اید | `sudo -u ipf3 bash -c 'set -a; . /etc/ipf3/server.env; set +a; /opt/ipf3/venv/bin/ipf3-server create-user admin --role admin --update'` |
